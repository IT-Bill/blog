最近我做了一个叫 **[ReFind](https://github.com/IT-Bill/refind)** 的 VS Code 扩展。它的目标很直接：**把“我想找什么”这件事，用自然语言说出来，然后让工具帮我生成正则表达式，并直接填进 VS Code 的查找 / 替换面板里。**

很多时候，我并不是不会写正则，而是**不想在上下文切换里浪费精力**：

- 脑子里已经知道自己要匹配什么
- 但还得停下来想转义、分组、边界和量词
- 或者去问一遍 AI，再把结果复制回编辑器里

这个流程不算难，只是烦。ReFind 想解决的就是这种“小麻烦”。

## 我为什么想做这个

我平时在 VS Code 里做代码修改时，常见的需求其实很像：

- 找出某一类函数调用
- 批量替换某种命名风格
- 只匹配满足某些上下文条件的文本
- 先试着搜，再决定要不要替换

这些事情用正则非常合适，但问题在于：**正则表达式的表达方式，和人脑描述需求的方式，不是一种语言。**

比如我更自然的想法往往是：

> 帮我找到所有 `snake_case` 的变量名，但不要匹配常量。

或者：

> 把 `foo(bar)` 这种调用替换成 `foo({ value: bar })`。

这种时候，如果工具能先听懂“意图”，再把它翻译成正则，会比我自己从头拼表达式顺手很多。

## ReFind 的核心体验

ReFind 现在主要做两件事：

### 1. 自然语言生成查找正则

你可以直接描述要找什么，扩展会调用语言模型，生成适合 VS Code 查找框的正则表达式，然后通过 VS Code 自带的能力直接应用到 Find Widget。

这件事最重要的一点不是“生成正则”，而是**生成后立刻能用**。我不需要再把结果复制出来、切回编辑器、打开查找框、再粘贴进去。

### 2. 自然语言生成查找 + 替换

除了查找本身，ReFind 也支持把“要替换成什么”一起描述出来。

也就是说，你可以一次性表达：

- 要匹配哪类文本
- 替换后的结果长什么样

这样更适合做一些半结构化的批量修改。

## 交互上我刻意保留了“确认”这一步

虽然这个工具用了 AI，但我并不想把它做成一种“黑箱自动操作”。

所以 ReFind 的一个关键设计是：**先生成，再确认，最后应用。**

也就是说，模型给出结果后，用户可以：

- 直接应用
- 手动修改
- 取消本次操作

我觉得这是个很重要的平衡点。因为正则这种东西，一旦写偏，影响范围可能非常离谱。相比“全自动”，我更偏向**可控的半自动**。

## 为什么要把当前选区作为上下文

另一个我觉得很实用的小设计，是把当前编辑器里的**选中文本**作为可选上下文。

这是因为很多查找需求都不是孤立的。用户真正想表达的通常是：

- 在“这段代码”附近找某种模式
- 按“这个例子”的形式生成一个对应的正则
- 参考当前选中的内容理解命名、结构或者格式

如果只给模型一句抽象描述，生成结果很容易泛化过头；但如果加上一小段用户明确选择的上下文，结果通常会靠谱很多。

当然，这里也有边界：**只有用户确认要带上选区时，选中文本才会发送给模型。**我不想让这个扩展默认偷看整个文件内容，这在体验和隐私上都不对。

## 这个项目里我比较在意的点

### 少折腾，少复制粘贴

我不太喜欢那种“AI 很强，但使用路径很绕”的工具。ReFind 的思路一直很朴素：

1. 在编辑器里提出需求
2. 得到正则
3. 审一眼
4. 直接应用

如果一个工具在“帮你省事”之前，先制造了一堆操作步骤，那它其实没有真的帮到你。

### 尽量贴近 VS Code 原生体验

ReFind 并没有试图重新造一套搜索 UI，而是直接接到 VS Code 已有的查找 / 替换流程上。这背后的想法也很简单：

- 用户已经熟悉原生 Find Widget
- 原生能力更稳定
- 少造轮子，维护成本更低

对我来说，一个好的编辑器扩展不一定要“看起来很大”，但最好能**自然地嵌进已有工作流里**。

## 目前的限制

这个项目还很早，所以限制也挺真实：

- 模型有时会给出不够理想的正则
- 复杂需求往往还是需要手动微调
- 目前主要面向 VS Code 的 JavaScript 风格正则
- 某些替换细节仍然受 VS Code 原生能力约束

所以我现在对它的定位更接近：**一个帮你把第一版正则快速写出来的工具**，而不是“百分之百替你完成复杂文本变换”的魔法按钮。

## 接下来我想做什么

如果继续往下做，我比较感兴趣的方向有几个：

- 多轮 refinement：例如“这个不错，但再把注释排除掉”
- 更直观的 regex 预览和高亮反馈
- 历史记录，方便复用之前生成过的模式
- 支持多文件搜索场景
- 更灵活的模型配置

这些方向本质上都在服务同一件事：**让“描述意图”到“完成编辑器操作”的距离更短。**

## 最后

我一直觉得，AI 工具真正舒服的状态，不是让你惊叹它多聪明，而是让你慢慢忘记它的存在——因为整个流程已经顺到像编辑器本来就该这样工作。

ReFind 还在很早期，但它已经是一个我自己会想用、也愿意继续打磨的小工具了。
